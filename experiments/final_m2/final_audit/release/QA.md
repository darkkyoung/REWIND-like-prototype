# 발표 예상 질문과 답변

**1. 원본 REWIND와 M2의 기술적 차이는 무엇입니까?**

원 연구는 egocentric 관측의 2D 불확실성과 시간 문맥을 활용하고, 전신 복원과 효율적인 추론을 다룹니다. M2는 Body22 teacher의 GT Stereo2D 입력과 DDIM10 복원을 고정했습니다. 우리가 구현·비교한 부분은 전체 teacher 선택, 연결 방향에 따른 기하 보정, 관측 기반 선택 게이트, 지속·순간 오류의 이중 경로입니다. 원 연구의 2D uncertainty나 temporal attention을 신규 기여로 세지 않았습니다.

**2. 왜 GT2D와 zero-camera를 썼습니까?**

기존 학습·추론 계약을 유지하면서 동일한 관측과 동일한 예측에서 보정 자체의 효과를 비교하기 위해서입니다. 실제 detector의 confidence, 가림, 카메라 오차는 이 설계로 판별할 수 없습니다. GT valid mask는 데이터의 유효성 표지입니다. 양안 재투영을 신뢰도 점수로 사용하지 않았습니다.

**3. 뼈 길이가 좋아지는데 왜 RR JPE는 커집니까?**

길이는 두 관절 사이 거리 한 개만 제한합니다. 관절 위치는 방향과 상위 관절의 오차에도 영향을 받습니다. 관절의 전역 오차 벡터를 eⱼ, 골반의 오차를 e₀라고 하면 Global은 ‖eⱼ‖, RR은 ‖eⱼ−e₀‖를 평균합니다. 같은 이동이 두 거리를 서로 반대로 바꿀 수 있습니다. Taunt16에서는 골반 오차가 10.1682 raw로 고정됐는데도 Phase 2의 16프레임 모두에서 이 현상이 발생했습니다.

**4. Phase 2·3·4가 각각 도입한 것은 무엇입니까?**

Phase 2는 Train300 연결 길이 중앙값을 기준으로 원래 연결 방향을 유지하며 제한된 거리만큼 자손을 옮겼습니다. Phase 3는 연결·이웃의 편차와 관측 innovation/누락을 함께 확인하고, 신뢰 가능한 과거 예측으로 시퀀스 길이 추정치를 갱신했습니다. Phase 4의 A는 같은 방향의 편차가 5프레임 지속된 작은 subtree를, B는 관측 이상과 3D innovation이 함께 나타난 연결을 처리했습니다. 두 제안이 반대 방향이면 목표 이동은 0이며, 시간 변화량 상한 때문에 이전 이동량은 잠시 남을 수 있습니다.

**5. 기존 Validation 개선이 Taunt16 전체 성공으로 이어지지 않은 이유는 무엇입니까?**

기존 15조건 평균에서 Phase 2의 RR 변화는 Control 대비 −0.254 raw였지만 Taunt16에서는 +0.154였습니다. Phase 3는 실제 출력이 Control과 같아 엄격한 개선 조건을 만족하지 못했고 Phase 4는 RR·FDE에서 탈락했습니다. 동작·인물·오염 구성의 차이가 함께 있어 원인을 하나로 특정할 수 없습니다. 대상 인물의 실제 뼈 길이가 Train prior와 다르다는 설명은 아직 가설입니다.

**6. Taunt16을 독립 Test라고 부를 수 있습니까?**

동작과 범위, 정책, 판정 기준을 추론 전에 고정했습니다. 기존 534 anchor와 동작 이름, float32 입력 및 GT의 정확한 중복은 없었습니다. 다만 리타게팅·반전이나 동일 원본 mocap 사용 가능성은 확인되지 않았습니다. 따라서 이번 근거는 추가 clean 동작 진단에 한정됩니다.

**7. 실제 지연시간은 얼마이며 실시간 처리가 가능합니까?**

Tesla T4에서 동기화한 Control infer_frame은 첫 프레임 868.89 ms, 후속 15프레임 평균 60.37 ms였습니다. 별도 warm-up이 없었습니다. 같은 Colab에서 CPU 후처리만 재생한 평균은 0.225/0.944/0.299 ms였습니다. RGB frontend, 모델 로드, prior 산출은 제외됐고 원본 FPS도 미확인입니다. 장시간 end-to-end 처리량이나 실시간 달성을 주장할 근거는 부족합니다.

**8. 다음 reliability-aware refinement는 무엇을 개선해야 합니까?**

지속 편차가 큰지에 더해, 한 연결을 이동시킬 때 각 자손의 상대 자세와 다음 프레임 변위가 얼마나 바뀔지 평가해야 합니다. 유익한 수정과 큰 손실을 일으키는 수정을 분리하는 것이 목표입니다. train에서만 기준을 정하고 독립성이 확인된 여러 motion, 실제 frontend, 충분한 고속 구간에 고정 평가해야 합니다. 이번 릴리스에서는 새 정책을 학습하거나 적용하지 않았습니다.

**9. FastGap이 줄었는데도 FAIL인 이유는 무엇입니까?**

FastGap은 GT 이동량 상위 사분위 전이에서 예측/GT 평균 이동량 비율이 100%와 얼마나 다른지 나타냅니다. 방향 오차는 반영하지 않습니다. Taunt16의 사전 기준은 FastGap 비악화 외에 네 오차의 엄격한 감소를 모두 요구합니다. 빠른 전이도 총 4개뿐입니다.

**10. 계산량을 줄인 연구입니까?**

Phase 1은 teacher를 두 번 실행해 출력 중 하나를 선택했습니다. Taunt16은 한 teacher를 한 번 실행하고 저장 자세에서 정책을 비교했습니다. 측정 대상과 조건이 달라 두 수치로 속도 개선율을 산출할 수 없습니다. One-step Student와 Adaptive DDIM은 수행 범위 밖입니다.
